## Findings worth putting in the README

These came out of the extraction and the ledger. They are the spine of the submission.

1. **The budget is a supply calculation, not a preference.** See above — 2.72T is the ceiling.
2. **S3's plan had exactly the wishful accounting this rubric punishes.** `../S3/assignment/DESIGN.md`
   gave the agentic lane 4% of 8T = **320B tokens**. Real agentic supply is **627M**. This plan
   corrects it and shows the arithmetic. S3's 8T budget and 15%-of-schedule anneal also need
   explicit reconciliation against S5's 2.4–4T and 2% anneal.
3. **Agentic must be defended in supervised tokens, not raw ones.** The trajectory widget measures
   53% supervised on a full multi-step run and 43% on a one-shot call. Applying those to the slot:
   360M raw trajectory → 191M supervised, 267M raw function-call → 115M supervised, **306M total**.
   Demand at the floor is 49.4B; **94.9% must be built**, even at the 4-epoch ceiling.
4. **Fixing the proxy is not a substitute for the floor.** Measured on the OPUS widget at keep 40%:
   English-heavy proxy, floor off → Indic **0.0%**, agentic **0.0%**. Balanced proxy, floor off →
   Indic **19.7%**, agentic still **0.0%**. Floor on → Indic 13.0%, agentic 16.3%. Indic starves
   because the proxy is English-shaped; agentic starves because trajectories look low-utility to
   *any* benchmark-derived proxy. Only the floor saves agentic. The session's prose does not make
   this distinction — the widget does.
5. **The widget's own default Indic tier split is unsatisfiable against its own inventory.** It
   ships A 40 / B 25 / C 20 / D 15, but the entire translated tier (Samanantar 2B + BPCC 3B) is
   **5B tokens**. A 20% translated share of a 378B lane would need 75.6B — 15 epochs. Hence the
   supply-derived split above, where translated is 2.6%.
6. **59% of the Indic slot is already synthetic before we generate anything.** 276B total =
   114B real + 162B synthetic (Sangraha synthetic alone). Every Indic dataset in the inventory is
   AI4Bharat — there is no second supplier for the flagship capability.
7. **Long-context supply is not new supply.** Both rows (repo-packed code 60B, book-length 40B) are
   repackings of tokens already counted in the code and web slots.
8. **The reasoning slot is one corpus.** 92% of the 85.1B is V4-lineage AON (78B); all the open
   reasoning-trace sets together are ~7.1B.
9. **The long-context lane has no benchmark.** The composer points it at `long-eval`, but the
   benchmark explainer has no long-context group at all — 18 benchmarks in agentic / coding /
   reasoning / Indic only. Any plan funding this lane must name its own eval.
10. **Transition stability is dominated by frozen embeddings, not shift size.** Measured:
    max sharpness + frozen + no warmup → **151×**; same shift, trainable embeddings → **8.0×**;
    frozen + 3B warmup → 6.0×; frozen + 5B warmup → 3.4×. The only configuration under the
    widget's hard-coded **3× threshold** is moderate sharpness (0.4) + 3B band + trainable
    embeddings → **1.5×**. Warmup alone does not rescue a maximal shift.
11. **Ultra reasoning is measurably wasted on easy problems** — the widget's own verdict: 346 tok
    for 95%, only +4 points over HIGH's 161 tok / 91%. This is the argument for scheduling trace
    length rather than always training long.

### Step 4 — the proxy ablation
Five arms, identical architecture / optimiser / seed / token count, differing **only** in mixture:

| Arm | Mixture | What it tests |
|---|---|---|
| A | The proposed V5 main-pretraining mixture | the hypothesis |
| B | Naive web-heavy (V4 start: web 72 / code 13 / STEM 7) | does composing backward from benchmarks beat the default? |
| C | Arm A with the protected floor removed, selector free | **does the floor earn its cost?** |
| D | Arm A with Indic collapsed to verified-only (no translated/synthetic) | does the four-tier split beat verified-only-plus-repetition at equal tokens? |
| E | Arm A with the stage transition as a hard step, no warmup band | reproduces the gradient-spike claim at small scale |

**Metric:** per-domain held-out **bits-per-byte** (not raw cross-entropy — bpb is comparable
across languages and tokenizers) on six domain-matched validation sets: general web, code,
math/reasoning, agentic trajectory (loss on assistant tokens only, observations masked),
long-context, verified Indic. Plus grad-norm trace for arm E.

**Declare the decision rules before running.** A is confirmed if it beats B on Indic and agentic
bpb by more than the seed-noise band while giving up no more than a stated amount of general-web
bpb; the floor is justified if C degrades Indic/agentic materially; the four-tier split is
justified if A beats D. Establish the seed-noise band by rerunning one arm with a second seed.
**Report refutations as refutations** — negative results are the evidence that it was tested.

**Data:** S4's cleaned shards for the Indic lane (43.45M tokens — at a 12% share of a ~600M-token
arm that is ~1.7 epochs, itself a live demonstration of the repetition pressure the plan argues
about), plus small pulls for the other lanes. Reuse the S4 `sarvam1` tokenizer so fertility
numbers stay comparable. Code in `proxy/`, results to `proxy/results.json` + `proxy/RESULTS.md`.
